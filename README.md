# SoftLanding

A quiet three-screen demo for the wait between a medical test and its results. It offers sensory grounding, never medical answers.

## Flow

1. Splash screen.
2. Write or dictate a fictional concern. With an ElevenLabs key the recording is transcribed by Scribe; otherwise the browser's own speech recognition is used. Typing and device dictation remain alternatives.
3. One grounding scene: a brief acknowledgement, a gently receding thought balloon, a soft light, and one invitation at a time in touch → see → hear order, spoken aloud in an ElevenLabs voice that can be switched off.

“I did it” and “Skip” advance. “Go back” revisits the previous invitation, or returns to writing from the first. Nothing advances automatically. The final message is exactly “The thought can still be there. And so can you.” Close clears the session and returns to the splash screen.

## Run

```sh
npm install
npm run dev
npm test
npm run build
npm start
```

Development runs at http://localhost:5173; production runs at http://localhost:4173.

## Configuration

Set these in the server environment or an ignored local `.env`. Both the dev server and `npm start` read `.env`; real environment variables take precedence. Never prefix a secret with `VITE_` or commit it.

| Variable | Effect |
| --- | --- |
| `ELEVENLABS_API_KEY` | Enables Scribe transcription and the spoken guidance. |
| `ELEVENLABS_AGENT_ID` | Enables the agent that reads the person's text. |
| `ELEVENLABS_VOICE_ID` | Voice for the guidance. Defaults to a calm narration voice. |
| `ELEVENLABS_STT_MODEL`, `ELEVENLABS_TTS_MODEL` | Model overrides. Default to `scribe_v1` and `eleven_flash_v2_5`. |
| `ANTHROPIC_API_KEY`, `ANTHROPIC_MODEL` | Alternative generator, used only when no agent is configured. |

Restart the dev server after changing configuration. `GET /api/status` returns `{ ai, voice, agent }`: which keys are present, not whether the upstream services are healthy.

## AI and fallback

`POST /api/grounding` routes in this order: local safety checks, the ElevenLabs agent, Anthropic, then the predefined invitations. It returns `{ experience, suggestion, source }` or `{ support: "urgent" | "symptoms" }`.

The agent returns the organiser schema from the plan, deciding which of the person's words to keep, which single logistical step is available, and which loop they are caught in:

```json
{"can_do":[{"label":"…","suggestion":"…"}],"cannot_know":[{"label":"…"}],"pattern":"…","human_support":false}
```

`shared/organised.mjs` sanitises that output and assembles the meditation from **pre-approved invitations**, one set per loop (searching, lying awake, thoughts running ahead, not knowing when). No sentence generated by the agent is read out or displayed as guidance; only the thought label, taken verbatim from the person's own text, and one validated practical step survive. The invitation sets are covered by the grounding validator in tests.

This is a deliberate constraint, not a limitation of the API: the agent's own prompt is fixed in the ElevenLabs dashboard and this workspace key has no `convai_write` permission, so per-conversation prompt overrides are refused. To let the agent write the guidance text itself, change its prompt in the dashboard to return the grounding schema below; `handleAnalyze` already accepts either shape.

```json
{"recognition":"string","thought_label":"string","grounding":{"touch":"string","see":"string","hear":"string"}}
```

Shared validation checks exact keys, three distinct modalities, sensory language, sentence and word limits, faithful extractive labels, and prohibited clinical/reassurance language. Rejected output, timeouts and unavailable APIs use three predefined invitations. These conservative text checks cannot guarantee the absence of every possible unsafe semantic claim. The fallback intentionally does not pretend to be generated.

## Voice

`POST /api/transcribe` takes one recording as the raw request body and returns `{ text }`. The writing screen records with `MediaRecorder` and sends the audio once the person stops speaking; nothing is streamed while they talk and nothing is stored.

`POST /api/speak` takes `{ text }` and returns MP3 audio for one line of guidance. Lines are capped at 300 characters, cached for the process lifetime, and rate limited per caller so a public demo cannot drain the quota. The grounding scene speaks one invitation at a time and reads identically with the voice switched off.

The ElevenLabs key stays on the server. The browser never sees it.

## Privacy and support

Use fictional concerns for the demo. Text is held only in memory, never logged or saved by this app, and cleared on Close or support routing. AI generation sends text to Anthropic. Browser dictation may use an external speech service; the writing screen discloses both. This app does not control those providers’ retention policies.

Simple English and Portuguese phrase checks run before generation on both client and server. Immediate-danger or new/worsening-symptom matches route to human support instead of grounding. These checks are limited safeguards, not clinical triage. Support contacts are explicitly for Portugal (112 and SNS 24).

## Verification

`npm test` covers schema validation, prohibited claims, fallback, server failures and support routing. Browser checks cover the three-screen flow, forward/back/skip, final copy, clearing on Close, support routing, and the mobile scene. Live microphone and live model output require manual verification with the relevant permissions and server key.
